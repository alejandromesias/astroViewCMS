## What a site must satisfy today

1. **Packages.** The CMS does not install a site's packages. Every package the site imports (the Astro config, pages, layouts, components) must be in the workspace `node_modules` (F1).
2. **Astro.** The build uses the workspace's Astro, not the site's own pin. The template's 7.4.13 and the workspace's 7.4.12 were compatible here, and no version error appeared. Class (b) produced no failure.
3. **Astro.site.** A page must not read `Astro.site` until F6 is fixed. A stock template layout does (`BaseHead.astro`), so today a stock template cannot be edited in the editor.
4. **Preview site config.** It lives inside the workspace (`previewSiteConfig`). Its `buildTimeFields` names only files the site has, and its `readOnlyCollections` names only collections it has. `--root` replaces its `root`.
5. **Manifest.** The build must write `documents.json`, `routes.json` and `schema.json`. A build that does not write them must fail (F2, F3).
6. **Content.** Collections load through `astro:content` with glob loaders. Markdown and MDX documents both appeared in `GET /api/documents` (`.md` and `.mdx`).
7. **Git.** The site's remote has a `main` branch. A local path worked. A GitHub remote needs the machine's credential helper or SSH key (run guide, section 3).
8. **Save.** `PUT /api/changes` takes `{ changes: [{ document, baseRevision, data }] }`. For a Markdown document `data` is `{ data, body }`. A change to a field the build does not read saves with `rebuild: false`.
9. **Publish.** `POST /api/publish` takes a JSON content type and no body. It makes one squashed commit on the branch with the CMS author. A build runs after it.
10. **Editor page.** The page at `/` must render at `origins.cms`. With F6 unfixed, no site whose layouts read `Astro.site` can be edited.
11. **Node.** The template's `engines.node` is `>=22.23.4`. The workspace runs on Node 26.
